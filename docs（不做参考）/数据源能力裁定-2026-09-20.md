## 0. 我 v1 错在哪（方法论层面，比结论更重要）

**错法**：我看到 `HanimeManager.kt:32`：
```kotlin
fun getHanimeSearchLink(artist: String) = HANIME_BASE_URL + "search?query=" + artist
```
就断定「站点没有作者页，项目自己把作者映射成搜索关键词」。

**错因**：`HanimeManager.kt` 那批 `get*Link()` **是给"分享文本"用的链接构造函数**（同一个文件里还有 `getHanimeShareText` / `getHanimeSearchShareText`），**它不代表站点的能力边界**。我把"项目选择用搜索来展示作者"误读成了"站点只有搜索"。

**而真正的能力边界在 `data/network/service/` 里实际 GET/POST 的 URL**——那里 `HanimeMyListService.kt` 早就有一整套 `/user/{uid}/...` 端点，**那就是作者页/用户主页的端点族**。我只查了一半就下结论。

**修正后的判定规则**：
> 判定「站点有没有某端点」**只能以 `data/network/service/` 下实际构造的 URL 为准**。
> `HanimeManager.kt` 的 `get*Link()` / `HanimeUrlRegex.kt` 只描述"项目当前怎么用"，**不描述站点有什么**。

## 2. 逐条修正裁定

### ✅ 作者页 —— 端点族已存在，缺的是「公开主页」这一层

**已有（代码可证）**：

| 端点 | 位置 | 现状 |
|---|---|---|
| `GET /user/{uid}/{listType}?page=N` | `HanimeMyListService.kt:37-43` → `NetworkRepo.kt:104` → `Parser.kt:769 myListItems` | 全套都在，**但只被用于"我自己的"清单** |
| `GET /user/{uid}/histories?sort=&page=` | `HanimeMyListService.kt:45-54` → `Parser.kt:801` | 同上 |
| `GET /user/{uid}/playlists?page=N` | `HanimeMyListService.kt:227` → `NetworkRepo.kt:284 getPlaylists` → `Parser.kt playlists` | 同上 |
| `GET /user/{uid}/edit` | `HanimeMyListService.kt:56-58` → `Parser.kt:813 userAccountPage` | 编辑资料页（**不是公开主页**） |

**关键洞察**：`getMyListItems(userId, listType, page)` **本身就接受任意 userId** —— 站点返回的是公开列表，所以**技术上只要把"自己的 uid"换成"作者的 uid"就能读到作者的作品列表**。目前调用方（`MyPlayListViewModel` / `MyListSubViewModel` / `OnlineListsBackup`）全都传的是当前登录用户，**没有一处用于看别人**。

**缺什么**：
1. **不带 listType 的裸主页 `GET /user/{uid}` 既没有 service 方法、也没有解析器** ← 如果作者页要做成完整主页（头像/名字/简介/作品网格），这一层要新增
2. **`artistId` 与 URL 里数字的对应关系未确认**：`Parser.kt:620-621` 同时解析了 `input[name=subscribe-user-id]` 和 `input[name=subscribe-artist-id]`，**哪个等于 `/user/{数字}` 里的数字需实测**
3. UI 路由

**成本修正**：原来判「做不了」→ 实际 **M**（若首版只做"复用 `myListItems` 拉作者作品网格 + 简单头部"，可压到 **S**）
**还需实测**：`/user/{uid}` 的 DOM 结构（写出解析器前必须看一眼真实 HTML）

## 5. 本次教训（已写入长期记忆）

1. **判定站点能力边界看 `data/network/service/` 的实际 URL**，不看 `get*Link()` 助手函数
2. **判定"站点认不认某参数"，看已有功能是否在用**，而不是看参数表是不是打包资源
3. **判"能不能翻页"要看 service 方法有没有 `page` 参数**，不要凭"数据来自 HTML"就断言不能分页
4. 下"站点不支持"这种**否定性结论**前，必须把端点族查全——否定性结论的举证责任更高
