## 维护约定

1. **新增文档**：放顶层，并在本文件的「现行文档」表里登记一行。
2. **文档失效时**（做完了 / 被取代 / 结论被推翻）：`git mv` 进 `history/`，文件名加 `.<YYYY-MM-DD>归档.md`，并在「历史文档」表里写清**为什么失效**。「做完了」和「结论错了」要分开写，后者更危险、更该说清楚。
3. **别在顶层留同主题的多个"实施规划"**。要么取代旧的（旧的下沉并写明取代关系），要么合并。
4. **本目录的文档不可作为代码事实的依据**。凡涉及"某功能是否已实现 / 站点是否支持某端点"，以**实际读取的代码**（附 `文件:行号`）为准，或以站点实测为准。文档只回答"当时是怎么想的"。
