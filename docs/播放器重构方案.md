# 播放器重构方案：布局与组件样式对齐 animeko

> 制定：2026-09-15（三路深读 reference/animeko 后定稿）
> 目标：详情页布局 + 播放器组件样式向 animeko 看齐，信息排列保留我们的，
> 顺带用它的生命周期纪律治闪退。
> 红线：animeko 是 **AGPLv3**，只学结构与数值，**不整段搬代码**（clean-room 重写）。

---

## 一、对照结论（只写影响决策的）

### 布局：和我们的设计稿基本同构，差三处

- animeko 窄屏 = 顶置 16:9 播放器 + 详情/评论双 Tab + HorizontalPager；
  宽屏（≥840dp）= 左播放器拉伸 + 右栏 340–460dp 同 Tab。断点同为 840。
  ——与 [`详情页布局设计.md`](详情页布局设计.md) 一致，**不改方向**。
- 三处差异：① 右栏宽度是 `maxWidth*0.25 clamp 340–460dp`（我们固定 360/320，
  可抄）；② 简介不在播放页展开（标题点开弹详情，简介 5 行折叠）——我们保留展开，
  这是"信息排列保留"的一部分；③ 无相关推荐 Tab（相关在简介底部）——我们右栏
  要相关 Tab（用户已定），保留。
- 参考路径：`reference/animeko/app/shared/src/commonMain/kotlin/ui/subject/episode/EpisodePage.kt`
 （路由/分叉 `:82,332,304`，窄屏 `:683`，宽屏 `:459`）。

### 播放器样式：抄数值

- 叠层：顶 scrim `Transparent→0.72/0.45`、底反向（`VideoScaffold.kt:173-182`）；
  按钮 36dp、全屏 32dp；进度条容器 24dp、轨道 6dp、thumb 12×24（`MediaProgressSlider.kt:358-587`）。
- 播放器强制暗色（`EpisodeVideo.kt:274` 外套 dark theme），颜色只用 colorScheme +
  weaken 系 alpha（0.618/0.5/0.382），无自研色板。
- 手势映射：单击切显隐、双击暂停（触屏）/全屏（鼠标）、左右滑 seek、左亮右音、
  长按 3x 速、键盘 `Space/←→/F/B`（`PlayerGestureHost.kt`、`PlayerKeyboardShortcuts.kt:52`）。
- 状态态：缓冲/错误中央 floatingMessage，失败红色 error 文；播完无重播页（靠选集+下一集）。
- 参考路径：`reference/animeko/app/shared/video-player/src/commonMain/kotlin/ui/`
 （`VideoScaffold.kt`、`PlayerControllerBar.kt`、`gesture/`）。

### 生命周期：治闪退的关键三条纪律

1. **播放器不动**：播放页无 `movableContentOf`、无共享元素（`SearchPageResultColumn.kt:204`
   明写 "Shared transition disabled to avoid detach/lookahead crashes"）；
   全屏只是同一 composition 隐藏兄弟节点，实例零移动。
   ——我们正好全犯：`movableContentOf` 跨分支搬 Surface（`03bae00`）、封面共享元素、
   随滚折叠改尺寸。闪烁+必现崩溃与"渲染面被移动/反复重配"高度吻合。
2. **失败即停**：异常→`Failed` 状态，先 `stopPlayback`，靠上层换源或手动重试；
   **没有"同一 URL 静默自动重试"**（`PlayerSession.kt:112-153`）。
   ——我们的 1.5s 自动重载（`7892871`）在纹理未释放时再开一流，是 UAF 的完美帮凶，先删。
3. **切集复用实例**：`setMediaData` 切片，不重建 player（`EpisodeFetchSelectPlayState.kt:134-197`）。
   ——我们 `remember(videoCode)` 切片重建引擎，可改为复用（与切集逻辑一起做）。

## 二、重构范围

### R1 播放器不动（治崩，P0，先做）

- 删 `VideoShellContent` 里 `movableContentOf` 跨分支搬播放器：改回"单组合路径 +
  条件 modifier"（学 animeko 全屏做法：显隐兄弟节点，不换分支）。
  代价：`03bae00` 解决的分支切换黑帧可能回来——用"同一 composition + 可见性切换"
  解，而不是搬运。需回归窗口跨 840dp。
- 封面→播放器的共享元素过渡下掉（或至少排除视频面，只过渡封面图）。
- 随滚折叠暂缓合并（已提交的不回退，但默认关闭/藏开关，等崩溃消失再议；
  它改 Surface 尺寸，与"不动"冲突）。

### R2 失败即停（治崩，P0，同批）

- 删 1.5s 同 URL 自动重试；错误卡保留手动重试（已有）。
- 错误态样式对齐 animeko：中央红色 error 文 + 速度/超时提示位。

### R3 布局对齐（体验，与 B 节合并）

- 右栏宽改 `25% clamp 340–460dp`；窄屏顶置 16:9 随宽自适应（已是公式，保留）。
- 简介/选集/评论/相关顺序保留我们的（用户已定），Tab 结构保留。
- 播放器强制暗色叠层（与主题解耦，省掉浅色下的叠层 token 债）。

### R4 组件样式对齐（体验，排后）

- scrim/按钮/进度条数值按 §一抄；手势映射对齐（双击暂停/全屏分端、长按速播、键盘）。
- 颜色收敛到 colorScheme + alpha（不动色板，等系统性设计）。

### 保留我们的（不碰）

- 信息排列（简介选集优先、右栏相关/评论 Tab、窄屏双 Tab）。
- 登录/CF/代理/UA 透传、超分 shader、GIF/截图、PlayerTrace 埋点、超时。
- 切片引擎重建→复用可az后做（R1 先保不崩）。

## 三、实施顺序与验收

1. R1 + R2（治崩）：改完用户跑必现场景——**硬验收：连续播 3 部片子不崩不闪**。
2. R3（布局）：右栏宽 + 暗色叠层，小步回归。
3. R4（样式手势）：逐项对齐，每项可独立回退。
4. 回归清单：窗口跨断点、全屏进出、切片、选集、错误重试、PiP。

## 四、风险

- AGPL：只看结构数值，代码自己写；评审时重点看"像不像抄"。
- `movableContentOf` 拿掉后分支切换黑帧可能回来——这是已知代价，用单组合路径解，
  若解不掉则保留 movable 但**排除视频面**（只搬控制层）。
- 自动重试拿掉后弱网会更快落到错误卡——符合"失败即停"，且手动重试还在。
