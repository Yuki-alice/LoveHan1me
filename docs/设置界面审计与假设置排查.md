## 〇、结论先看

**没有"凭空捏造"的开关**——80 个设置字段里，没有一个是「既无持久化、又无 UI、又无消费」的三无产品。
真问题不是"假的开关"，而是**同一份 UI 铺在三端，后端只有一端实现**：

| 等级 | 含义 | 处数 | 代表项 |
|---|---|---|---|
| **A 真·假设置** | 三端都无任何功能消费 | 1 | `showBottomProgress` |
| **B 跨端假设置** | UI 三端可见，后端只有 Android 实现 | 5 个开关 + 1 组（10 项） | `playerKernel`、MPV 高级设置、`secureMode` |
| **C debug 限定** | release / 桌面 / iOS 恒失效 | 2 | `displayDensity`、`alwaysShowUpdateCard` |
| **D 死字段** | 存了没人读 | 2 | `usageSourceVerified`、`usageSourcePending` |
| **E 诚实禁用** | UI 明确标"暂不可用" | 1 | `disablePredictiveBack` |
| **F 标注不一致** | 界面写的和代码里的不一样 | 1 | `longPressSpeedTime` 的"(默认)"标注 |

其中 **A 与 E 是继承自上游的同款问题**（参考项目里 `showBottomProgress`、
`disablePredictiveBack` 同样没有消费点），不是本轮去 fork 化引入的。
**B 类才是本项目的结构性新问题**——参考项目是纯 Android 单端，不存在"跨端可见性错配"这一层。

### 3. 桌面 MPV 参数下发：9 项补齐 / 1 项裁定为不可实现

在 `DesktopMpvPlaybackEngine` 新增 `applyMpvSettings(handle)`，与既有 `applyNetworkOptions`
同批、在 `setMediaData` **之前**执行，**每次 load 重发**（mediamp 的 player 跨视频复用，
只有重发才能"改完设置下一个视频生效"，也才能清掉上一个视频残留的 `video-sync`）。

下发：`profile` / `hwdec` / `msg-level` / `cache-secs` / `framedrop` / `deband` /
`network-timeout` / `tls-verify` / `interpolation`(+`tscale`/`video-sync`) / `customMpvParams`。
每条记录 `setPropertyString` 的返回值，`set=false` 的项集中进日志（mpv 部分选项只在初始化前可改）。

**`enableGpuNextRenderer` 裁定为桌面不可实现 → UI 隐藏该行。** 证据来自反查
`mediamp-mpv-desktop-0.3.2.jar`：`JvmMpvMediampPlayer` 自己写死了
`vo=gpu-next`/`vo=libmpv` + `gpu-context` + `gpu-dumb-mode` 的一整套组合（配合它自己的
render API 交帧），同时它还会设 `profile=fast` / `hwdec` / `user-agent`。
桌面改写 `vo` 会让渲染面收不到帧。换言之桌面上"用 gpu-next"本就是底色，没有可翻转的余地。

顺带消除一处双份实现：`customMpvParams` 的解析（`key,value;` 分号分隔）原本在
`androidMain/MpvPlaybackEngine` 里私有实现，现提到 commonMain
（`core/util/MpvCustomParams.kt` 的 `parseMpvCustomParams`），两端共用 —— 避免同一串用户输入在两端理解不同。

### 3.2 B 类：跨端假设置 —— 桌面/iOS 上 UI 可见但后端为空

这一类的成因是**结构性的**：设置 UI 铺在 `commonMain`，但对应能力只有 Android 实现。

#### ① `playerKernel`「切换播放内核」——桌面忽略该参数

#### ⑤ `allowPipMode`「允许画中画」

`desktopMain/.../DesktopVideoPageHost.kt:12-30` 写得很清楚：


- `iosMain/VideoPlatform.ios.kt:10` —— **`= false`**

### 3.3 C 类：debug 限定 —— 2 项

`isDebugBuild()` 的三端 actual：Android = `BuildConfig.DEBUG`；
**desktop = `false`（硬编码）**；**iOS = `false`（硬编码）**（`core/util/IsDebugBuild.*.kt`）。

#### ⑦ `displayDensity`「应用显示密度」

`app/src/main/.../BaseActivity.kt:52`：

```kotlin
val densityScale = if (BuildConfig.DEBUG) settings.displayDensity.scale else 1f
```

→ **release 包恒为 `1f`**，用户在设置里改 75%/125% 完全不生效。
不过它的入口也在开发者选项内（`isDebugBuild()` 门禁），release 用户看不到，所以危害被"藏"住了。
真正的风险是：**将来一旦把开发者选项放开到 release，这个设置会立刻变成假设置。**

`SharedHomeScreen.kt:98`：`val showSimulatedUpdate = isDebugBuild() && settings.alwaysShowUpdateCard`
→ 同上，自洽（入口和消费都用同一门禁）。

### 3.4 D 类：死字段 —— 2 项
