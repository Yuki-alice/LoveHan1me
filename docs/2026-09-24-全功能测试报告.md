### 新增问题：iOS 高级筛选选项为空

位置：iOS 模拟机 → 发现 → 高级搜索 → 类型/排序方式。

现象：高级搜索面板显示“类型、排序方式、标签、品牌、发布日期、影片时长”六项，但打开“类型”或“排序方式”后，弹窗内容区域没有任何可选项，只显示标题和“重置/取消”。因此 iOS 端 C5/C6 无法完成筛选选择；桌面端同类筛选已验证可正常显示选项并生效。

建议：检查 iOS 筛选选项列表的 Compose 渲染/状态传递，补充至少“类型”和“排序方式”弹窗的 UI 测试断言。

## 6. 问题与风险

### P1：iOS commonTest 无法编译

位置：[StartupTraceTest.kt:31](/Users/kurisu/LoveHan1me/shared/src/commonTest/kotlin/lovehan1me/core/util/StartupTraceTest.kt:31)、[StartupTraceTest.kt:42](/Users/kurisu/LoveHan1me/shared/src/commonTest/kotlin/lovehan1me/core/util/StartupTraceTest.kt:42)。

影响：`shared:iosSimulatorArm64Test` 无法启动，iOS 测试结果不能作为发布门禁依据。

建议：移除 commonTest 中的 `Thread.sleep`，使用跨平台时间抽象；或把该两条时序测试拆到 JVM/desktopTest，并补充 iOS 可编译的等价断言。

### P2：Android 仪器测试缺少设备

影响：无法验证 PiP、防截屏、触感、媒体导出、屏幕方向、Android 下载通知等移动端能力。

建议：连接 Android 真机或启动 API 对应的模拟器后重跑 `connectedDebugAndroidTest`，并补齐 N/J/L 相关用例。

### P1：iOS 高级筛选弹窗没有选项

影响：iOS 发现页只能看到筛选面板，不能选条件和应用筛选；桌面端不受影响。

建议：修复 iOS 筛选弹窗的数据绑定/列表布局，并补测类型、排序、标签等条件的选择和恢复。

### 观察项：播放器进度拖动未形成稳定结论

本轮已验证播放/暂停与恢复，进度条拖动受桌面控件自动隐藏和坐标命中影响，未将一次不稳定操作判为产品缺陷。建议在后续自动化中增加可访问性语义或直接绑定播放器 seek 状态断言。
