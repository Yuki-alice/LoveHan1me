## F1 起服尾段的停止竞态（并收掉桌面同族漏口）

**结论**：门面新增唯一一处"就绪发布"入口 `EchGateRuntime.publishRunningIfStillStarting(port)`，
在就绪锁内复查状态仍是 `Starting` 才落 `Running`；Android 起服器改用它（false 时就地
`close()` 并把这次起服当取消），`stop()` 与它共用同一把锁。**桌面监视器的就绪行也改走同一入口**
—— 那里有同族漏口（见下），之前没被列进审阅发现。

- 取证日：2026-10-02
- 环境：Gradle 9.4.1 / JDK 21 / Kotlin 2.4.10；`:shared:desktopTest`（JVM）
- 重跑：
  1. 基线：`./gradlew :shared:desktopTest --tests "lovehan1me.data.network.EchGateRuntimeTest" --tests "lovehan1me.data.network.EchGateArtifactTest" --console=plain`
  2. 反向验证：`python3 /tmp/rv_echgate.py`（临时脚本，未入库；每轮先删
     `shared/build/test-results/desktopTest/*EchGateRuntimeTest*.xml`，`finally` 还原源码）
- 观测：
  - 基线 `EchGateRuntimeTest` **15 用例 / 0 失败 / 0 跳过**，`EchGateArtifactTest` 6 用例 / 0 失败
  - 反向验证 **PASS=6 FAIL=0 SKIP=0**（关掉规则 → 期望用例转红）：

    | 被关掉的规则 | 期望转红的用例 |
    |---|---|
    | `stop()` 先落 `Stopped` | `主动停止落 Stopped 且不记成失败` 等 4 条 |
    | `stop()` 先落 `Stopped` 再回收资源（顺序） | `停止时先落 Stopped 再回收资源` |
    | 就绪发布复查仍是 `Starting` | `起服期间被停止时就绪发布必须失败` |
    | 失败兜底只覆盖 `Starting` | `起服途中被停止不会把 Stopped 覆盖成失败` |
    | 未装配运行时落 `Failed` 并返回 false | `未装配运行时 start 落失败而非卡住` |
    | 起服不留终态时兜一次 `Failed` | `一个不留终态的起服器不会把状态卡在 Starting` |

  - **桌面同族漏口（本轮一并收掉）**：`DesktopEchGateStarter` 的监视器原本在读到就绪行时
    **无条件** `publish(Running)`。若这一行在 `stop()` 之后才从管道里被读出（已缓冲），
    状态会被覆盖回 `Running`，而进程侧的收尾因 `owned=false` 走
    `onProcessOutputEnded(false)` 原样返回 —— 留下一份**永久的假就绪**（开关已关、
    设置页显示在运行）。现改走同一入口。
  - **未能确定性钉住的一处**（如实记录）：`stop()` 与就绪发布共用锁，这一条是
    "复查状态 → 落就绪"与"落 Stopped"的全序保证；但把锁去掉后上述用例**仍会通过**
    （因为复查本身已经拦住了主竞态），所以锁只被推理保证、没有被用例确定性地钉住。
    真正被钉住的是复查判据与"先落 Stopped 再回收资源"的顺序契约。
- 失效条件：门面重构后脚本片段位置变化会让对应条目报 SKIP（脚本把 SKIP 计为未覆盖，
  不会静默变绿）；`EchGateStarter` 接口若增加"自己落状态"的方法，本节的两入口约定失效。

## F2 验证窗出站回落口径（按门面状态分两支）

**结论**：`GateWebViewProxy` 由"隧道 → 直连"单链改为**按门面状态分两支**：
网关是可用候选 ⇒ `隧道 + addDirect()`；否则 ⇒ **用户手填代理**（Http / Socks），
未配则不覆盖（＝系统代理语义）。判据全部取自 `currentEgressState()`。
**刻意不采纳**审阅建议里"隧道 → 用户代理 → 直连"的单链（理由见下）。

- 取证日：2026-10-02
- 环境：`androidx.webkit:webkit:1.17.1`；`:app` minSdk 29 / compileSdk 37
- 重跑：`./gradlew :shared:compileAndroidMain :app:compileDebugKotlin --console=plain`；
  判据对照 `shared/src/androidMain/kotlin/lovehan1me/app/web/GateWebViewProxy.kt`
  的 `overrideConfig()` 与桌面 `CloudflareCdp.proxyFlag()`
- 观测：
  - **为什么隧道后面接"直连"而不是"用户代理"**：网关是候选时，App 的 HTTP 层全部经
    网关出站，而代理选择器对**回环短路**，所以这条路的出口是**本机 IP**。
    隧道可用时 WebView 也走本机 → 同出口；隧道坏掉时落到 `addDirect()` 仍是本机 IP。
    若按建议改落用户代理，出口会变成**代理 IP**，与 App 反而不一致 ——
    正是"验证过了仍然要验证"的成因（`cf_clearance` 绑 UA + 出口 IP）。
    所以"用户代理"属于第 2 支（网关整个不在候选里时），不是隧道的失败兜底。
  - 第 2 支补上了一个**此前真实存在的缺口**：网关关着 + 用户在应用内配了 Http/Socks
    代理时，App 经 `HanimeProxySelector` 走代理出口，而 WebView 覆盖为空、仍走**系统代理**
    （通常没配）＝直连，两边出口不一致。现改为显式指向那个代理。
  - `ProxyState.SystemResolved` 与 `None` 都不覆盖：系统代理本就是 WebView 的默认出口，
    覆盖没有增量。
- 失效条件：桌面 `CloudflareCdp.proxyFlag` 的口径变化时两端必须同步改（本文件的第 1 支
  就是与它对齐的）；`ProxyConfig.addProxyRule` 若不再接受 `http` / `socks` scheme，第 2 支失效。

## C1 保存图片出口统一（Android）

**结论**：`saveImageToGallery` 的取图从**裸 `ImageLoader`** 改成经
`createCdnFetchClient()`（带 `HanimeDns` / `HanimeProxySelector` / `EchGateInterceptor`）
的常驻加载器，与浏览、下载、封面同一条出口 —— 与桌面 `HomePageUtils.desktop.kt` 早已采用的口径一致。

- 取证日：2026-10-02
- 环境：`:shared` androidMain；Coil 3（`OkHttpNetworkFetcherFactory`）
- 重跑：`./gradlew :shared:compileAndroidMain :app:compileDebugKotlin --console=plain`（编译期覆盖）
- 观测：
  - 改前：`ImageLoader.Builder(context).build()` 每次保存新建一个引擎 —— 既没有 DNS 兜底 /
    代理选择器 / 网关改写（开着网关或手填代理时"保存图片"必然失败，而同一张图在页面上显示正常），
    又每次调用各开一个连接池。
  - 改后：`private val galleryLoader by lazy { ... OkHttpNetworkFetcherFactory(callFactory = { createCdnFetchClient() }) }`，
    常驻且共享连接池。**MediaStore 写入逻辑未动**（仍走 Coil 解码 → `toBitmap()` → JPEG 落盘）。
  - 出口三件套的回归由既有 `CdnFetchClientTest` 覆盖（它钉的正是"CDN 抓取与浏览/下载同一条出口"）。
- 失效条件：`saveImageToGallery` 的调用方若改为直接给 URL 由 UI 层加载，本节结论失效；
  `createCdnFetchClient` 的出口配置变更时以它的测试为准。
