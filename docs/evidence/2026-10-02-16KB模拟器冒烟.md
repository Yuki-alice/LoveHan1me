# 16 KB 模拟器冒烟（A5 模拟器部分）

> 计划：`docs/plan/网络体验收尾.md`（真机验收 A5 的模拟器部分）；前序：
> `docs/evidence/2026-10-02-Android-ECH网关接入.md`。
> 范围：16 KB 页模拟器上的安装与端到端冒烟。**真机 A1–A4 仍待执行**。
> 过程中发现并修复两处只有真机/模拟器才暴露的阻断缺陷（见下，随本文件同笔提交）。

## 结论

`libgojni.so` 在 16 KB 页设备上正常加载，Go 运行时与进程内网关工作，浏览与图片
经网关端到端 200 —— **A5 的 16 KB 兼容性结论成立**。但冒烟同时暴露了两个平台级
阻断点，修复后才真正跑通（修复前首页为 `Load failed, please retry`）。

### 缺陷①：明文回环被 Android 网络安全策略拦下（已修）

- 现象：`CLEARTEXT communication to 127.0.0.1 not permitted by network security policy`，
  网关改写的请求全部被 OkHttp 拦掉并回退直连；受限网络下直连 RST ⇒ 首页失败。
- 依据：localhost 的隐式明文豁免要到 **Android 17（API 37）**才引入（官方"网络安全配置"
  文档），API 29–36 上应用必须显式配置。
- 修复：新增 `app/src/main/res/xml/network_security_config.xml`（只豁免 `127.0.0.1` /
  `localhost` 的明文，其余保持平台默认），在 `app/src/main/AndroidManifest.xml:35` 引用。
  该豁免覆盖进程内所有出站（OkHttp 浏览/图片/下载、播放器、验证 WebView 的代理连接）。

### 缺陷②：`ip-list` 传空 ⇒ 网关被污染的 DoH 结果带偏（已修）

- 现象：Android 起服器把 `--ip-list` 传空（原注释称"网关按域 DoH 自取"），网关自行解析
  `hanime1.me` 得到 Facebook 段地址（`185.60.218.50`），拨号 15s 超时；ECH 路径也试不通。
- 修复：新增 jvmMain 共享入口 `echGateSeedIps()`（"探测过能建连"的内置 CF IP 并集，
  桌面原有逻辑的抽取），Android 起服器改传种子（`AndroidEchGateStarter.kt:54`），
  桌面共用同一份（`DesktopEchGateStarter.kt:73`）。
- **iOS 壳仍传空**（`EchGateBootstrap.swift` 的 ip-list 参数），与修复前的 Android 同形状；
  需在 iOS 上复验后同步（iOS 无 `HanimeDns`，种子来源需另定）。已记入计划遗留项。

- 环境：macOS arm64 / Android Emulator 37.2.12 / 镜像
  `system-images;android-36;google_apis_ps16k;arm64-v8a`（AVD `han1me-16kb`，Pixel 7 档）/
  应用为单独构建的 debug 包（`./gradlew :app:assembleDebug`，含 arm64-v8a 与 x86_64 双 ABI）

  3. `emulator -avd han1me-16kb -no-window -no-audio -no-boot-anim -no-snapshot -gpu swiftshader_indirect -no-metrics`
  4. `./gradlew :app:assembleDebug`（单独跑，勿与 Release 同批）→ `adb install -r -g <apk>`
  5. `adb shell getconf PAGE_SIZE` → `16384`
  6. `adb shell am start -n me.lovehan1me.debug/lovehan1me.ui.activity.MainActivity`
  7. `adb logcat | grep -iE "EchGate|GoLog|CLEARTEXT"`；`uiautomator dump` 查页面结构

  - `EchGate: ECH 网关已就绪：127.0.0.1:<port>`；冷启动埋点 `ech-gate+395ms`（先于首帧 3183ms）
  - 修复后请求：`plan hanime1.me -> ips=[172.64.229.154 …] ech=true`；
    `hanime1.me -> 127.0.0.1:<port> (200)`；图床 `vdownload.hembed.com 被阻断，改用

    （模拟器性能，与 16 KB 无关）
### 修复的接线核对（提交前复核）

- APK 里确实带上了豁免：`unzip -l <apk> | grep network_security_config` →
  `res/xml/network_security_config.xml`（552 B）；
  `aapt2 dump xmltree --file AndroidManifest.xml <apk>` →
  `android:networkSecurityConfig(0x01010527)=@0x7f140004`。
  即"资源在包里 + manifest 指向它"两件都成立，不只是源码改了。
- 四模块用例（按 `settings.gradle.kts` 的 include 列表汇总）：`desktopTest` **576**、
  `testAndroidHostTest` **346**，均 0 失败 / 0 错误 / 0 跳过；
  `:app:assembleDebug`、`:desktopApp:compileKotlin` 与 iOS 两架构编译全部 BUILD SUCCESSFUL。
- 顺带更正了前两轮取证里"4 模块 421 / 257"的口径错误（漏算嵌套 `video/*`、
  多算非模块目录 `player/`），详见那两份文件里的口径说明。

- 失效条件：镜像 / emulator 版本更换、`network_security_config` 或 starter 的 ip-list
  参数变更、AAR 重构建后，本节结论需重跑；真机结论以真机实测为准（模拟器只证
  16 KB 兼容与端到端通路）。
