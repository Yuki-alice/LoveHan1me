# mediamp 0.5.0 后端能力（本机取证）

## `mediamp-mpv-android` 这个 AAR 里没有任何 native 库

- 取证日：2026-09-25
- 结论：AAR 只有 `R.txt` / `AndroidManifest.xml` / `classes.jar` / `aar-metadata.properties`
  四个条目，`.so` 数量为 0。也就是说 Android 侧要跑 mpv，libmpv 得自己带 ——
  这是"Android 不用 mpv 内核"的事实基础。上游 README 里"AAR bundles libmpv .so"那句与实测不符。
- 重跑：
  ```bash
  for v in 0.3.2 0.5.0; do
    curl -sS -f -o "/tmp/m-$v.aar" \
      "https://repo1.maven.org/maven2/org/openani/mediamp/mediamp-mpv-android/$v/mediamp-mpv-android-$v.aar"
    echo "$v size=$(stat -f%z /tmp/m-$v.aar) so=$(unzip -l /tmp/m-$v.aar | grep -c '\.so$')"
  done
  ```
  实测输出：`0.3.2 size=73223 so=0`、`0.5.0 size=79088 so=0`
- 环境：macOS / 直连 Maven Central / 2026-09-25
- 失效条件：上游开始分发 Android runtime（届时"Android 不能用 mpv"这条前提就不成立了）

## exoplayer 后端**有** `VideoAspectRatio` feature，旧文档说它没有是错的

- 取证日：2026-09-25
- 结论：0.5.0 的 exo 实现注册了这个 feature，且渲染侧真的用它 ——
  `reference/mediamp-0.5.0/mediamp-0.5.0/mediamp-exoplayer/src/androidMain/kotlin/ExoPlayerMediampPlayer.kt:378`
  `add(VideoAspectRatio, videoAspectRatio)`，实现体在 `:779-784`（一个 `MutableStateFlow<AspectRatioMode>`）；
  消费点在 `reference/mediamp-0.5.0/mediamp-0.5.0/mediamp-exoplayer/src/androidMain/kotlin/compose/ExoPlayerMediampSurface.kt:40`，
  底下是 `androidx.media3.ui.AspectRatioFrameLayout`（同文件 `:26`）。
  所以"换到 mediamp-exo 会丢画面比例"这句话不成立。
- 重跑：`grep -n "VideoAspectRatio" reference/mediamp-0.5.0/mediamp-0.5.0/mediamp-exoplayer/src/androidMain/kotlin/*.kt` 与该 sourceSet 下 `compose/`
- 环境：本机 `reference/mediamp-0.5.0`（gitignore，不在 CI；引用行号只在这台机器上可校验）
- 失效条件：mediamp 版本变更（当前钉在 `gradle/libs.versions.toml:66` 的 0.5.0）
