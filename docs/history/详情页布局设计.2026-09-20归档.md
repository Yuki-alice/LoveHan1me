# 视频详情页布局重设计方案

> 制定：2026-09-15（对比 YouTube / Bilibili / 原站后一问一答定稿）
> 前置：[`docs/视频播放优化.md`](视频播放优化.md) B 节。配色系统性问题另议，本文只动布局。

---

## 一、对比结论（为什么这样定）

| 维度 | 我们现状 | YouTube | Bilibili | 原站 hanime1.me |
|---|---|---|---|---|
| 播放器 | 公式高（16:9，封顶窗高 55%），单栏吸顶 | 左上 16:9，可剧场模式 | 左上，弹幕层 | 顶部播放器 |
| 首屏信息 | Tab 挡住简介选集 | 标题/UP主/操作行全在首屏 | 标题/数据/UP主在首屏 | 标题简介在下 |
| 相关推荐 | 简介页底部（窄屏）/ 右栏（宽屏） | 右 rail（经典） | 右 rail（选集/推荐） | 下方列表 |
| 评论 | 独立 Tab，与播放器互斥 | 播放器下方（曾测试放右 rail 被骂回） | 下方；下滑小窗悬浮续播 | 下方 |
| 窄屏 | 简介/评论双 Tab | 吸顶信息 + 评论下沉 | 小窗 + 长流 | 长流 |

取舍（YouTube 右 rail 评论被骂证明：**评论塞右栏是反模式**——但我们的右栏是 Tab 可切，
默认相关推荐，评论只是"可边刷"的选项，不抢首屏，所以成立）。

## 二、用户决策（2026-09-15）

1. **简介选集优先**：播放器下第一眼是简介 + 选集；评论和相关推荐成组放后面。
2. **宽屏右栏 = Tab（相关推荐｜评论）**：默认相关推荐，切评论可边看边刷。
3. **窄屏保留双 Tab**：简介 / 评论不变，相关推荐留在简介底部。

## 三、新布局 spec

### 窄屏（<840dp）：双 Tab，首屏让位

- 播放器：高度公式不变，**新增随滚折叠**——简介上滑时播放器缩成迷你条（标题+播控），
  下滑回弹。首屏从"播放器+半截 Tab"变成"播放器+简介标题+选集入口"。
- 简介 Tab（顺序即优先级）：标题 / meta（上传/播放量）/ 可展开简介 / actions /
  tags / **选集横滑** / 相关推荐（维持现状位置，算"成组"的窄屏形态）。
- 评论 Tab：不动（样式重设计另见 C 节，交互链路保留）。

### 宽屏（≥840dp）：左主右栏

- 左列：播放器 + 简介选集（同窄屏简介 Tab 内容，单页长流，不用 Tab）。
- 右栏（360dp / <1000dp 时 320dp，沿用 `PageMetrics`）：顶部小 Tab
  **相关推荐｜评论**，默认相关推荐；切到评论后列表独立滚动，播放器继续播（边看边刷）。
- Classic 横屏风格（设置项）保持：相关推荐进右栏，简介内隐藏（现状逻辑复用）。

### 不动

- 断点 840dp、右栏宽度、滚动记忆、选集 BottomSheet、评论数据/网络/弹窗链路。
- 配色、文案、图标（等资产齐了系统性设计）。

## 四、影响文件

- 必改：`VideoRouteHostScreen.kt:616-622`（高度公式 + 折叠态）、
  `VideoShellContent.kt:254-268`（单栏迷你条 + 宽屏右栏 Tab）、
  `VideoRouteContent.kt:52-59`（Tab 定义：窄屏简介/评论，宽屏右栏相关/评论）。
- 复用：`PageMetrics` 侧栏宽、`VideoTabsContent` 评论页、`ChildCommentScreen` 弹窗、
  `rememberLazyListState` 滚动记忆。
- 新增：迷你播放条组件、右栏小 Tab（可用现有 `PrimaryTabRow` 变体）。

## 五、实施顺序

1. 右栏 Tab（宽屏）：结构变化最小，先验证"边看边刷"。
2. 播放器随滚折叠（窄屏）：动高度公式 + 迷你条，需回归 PiP/全屏豁免。
3. 简介页内顺序微调 + 裸 dp 收 token（顺手）。
