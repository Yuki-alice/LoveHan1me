# LoveHan1me 项目重新定位梳理

> 日期：2026-09-20 ｜ 状态：已定稿（本文档取代此前所有归档规划，是当前唯一有效的项目级规划）
> 产出方式：代码事实盘点 + 逐项问答收敛，旧文档体系（P/M 阶段编号）全部作废。
>
> **2026-09-23 修订：路线图由四道 Gate 改为五道。**
> 原 Gate 2 的「播放器深度」方向独立为 **Gate 3「播放模块打磨攻坚」**，原 Gate 3/4 顺延为 Gate 4/5。
> 理由：播放模块的剩余工作（换底 mediamp、预览帧管线、超分诚实化、控件状态机、稳定性回归）
> 是**一个需要单独决策与单独验收的整体**，混在「功能纵深」里既看不清进度，也无法在
> 进入「齐整」之前被单独卡 DoD。进度勾选一律以 `docs/ROADMAP.md` 为准。

## 1. 定位

**LoveHan1me：独立演进的三平台（Android / Desktop / iOS）开源番剧播放器，双站点（Hanime1 + Getchu），体验标杆 animeko，从 Han1me 起家、半独立偶尔同步上游。**

关键身份转变：不再是"Hanime 的多平台 fork"，而是自己的项目，上游只是原料来源之一。

| 维度 | 结论 |
|---|---|
| 发布形态 | GitHub 开仓 + Release（APK / 桌面安装包 / iOS 源码+侧载说明） |
| 发布标准 | 三平台功能齐整、无 no-op 占位、体验对齐 animeko 才发第一版 |
| 上游关系 | 半独立，每月一次 cherry-pick 窗口，解析修复优先，UI 不动 |
| 平台优先级 | 三平台同等重要 |
| 站点策略 | 现有两站，不主动扩；竞争力来自对现有站点的覆盖纵深 |
| 投入模式 | 单人 + AI，稳定投入 |

## 2. 边界（Non-goals）

- 不扩第三站，不做站点插件化/社区扩展体系
- iOS 不追付费分发（无开发者账号）：Release 形态 = 源码 + Xcode 工程 + 自签侧载文档
- 不跟随上游大版本节奏

## 3. 现状盘点（代码事实）

**已具备的能力：**
- KMP 迁移基本完成：UI/业务全在 `:shared` commonMain（414 文件），`:app` 已是薄壳（28 文件，含 1 个 instrumentedTest，主代码 27）
- 多站点抽象 + 热切换（SiteIdentity / SiteSwitcher，最新提交刚补齐 javchu 切换边缘）
- 播放器三引擎（Android Exo / DesktopMpv / IosAVPlayback），animeko 式控件复刻中
- 双源弹幕（评论主源 + 弹弹增强：CommentDanmakuMapper + DandanplayApi）
- Room KMP / DataStore / Navigation 3 / commonTest（17 文件）/ build-logic 约定插件
- CI 双流水线：Windows（Android+Desktop 构建 + desktopTest）+ macOS（iOS 编译）
- 开源合规工具链：LICENSE / NOTICE / license_similarity_scan / find_orphan_strings

**架构债（Gate 1 素材）：**
- `:app` 剩 28 文件待归位（入口类保留，逻辑类下沉 `:shared/androidMain`，现有 55 文件）
- compileSdk 双版本（`:shared`=36 / `:app`=37，CI 需装双平台；收敛到单版本需同步降 targetSdk，属行为变更另立议题，见 gradle.properties 注释）
- 全仓 33 处 `TODO P5/P7`、`M6 契约` 等死编号引用
- 脚手架残留：P3aVerificationScreen、CookieSmoke、IsDebugBuild 假实现
- 站点热切换、双源弹幕刚落地，边缘补丁痕迹未收

**平台能力占位（Gate 4 素材，占位型 no-op，不含平台本无语义的 by-design no-op）：**
- iOS：触感反馈、相册写入、ImageLoader 特化、下载收尾（IosDownloadWorkController 已有骨架，VideoCacheStore 仍 no-op）
- Desktop：下载收尾（DesktopDownloadWorkController 已有真实现，PlatformStores 注释 stale 待更新）、调试构建对话框

**播放模块素材（Gate 3，2026-09-23 独立成 Gate）：**
- 播放器历史两次 revert（白屏/闪烁/每帧重建：468092b、f9d2cad、f4c2e4a），稳定性需回归测试护航
- 引擎抽象缝：`PlaybackEngine` 9 个默认空实现 + `PlatformVideoSurface` 必须向下转型，
  每个能力要三端各写一遍（详见 `docs/播放页-对比animeko差距清点与重构裁定.md` 与其审阅）

**体验风险（Gate 4 素材）：**
- 性能 live test（WatchFetchPerfLiveTest 等）随 desktopTest 默认跑、需联网易抖，尚无 CI 门槛/隔离策略

## 4. 路线图：五道 Gate

顺序严格不可跳，Gate 内自由排序。每道 Gate 有明确 DoD。
（2026-09-23 由四道扩为五道：播放器方向从 Gate 2 独立为 Gate 3，原 Gate 3/4 顺延。）

### Gate 1「收口」——让代码库只说一种语言

| 事项 | 代码证据 |
|---|---|
| `:app` 28 文件归位：入口类（MainActivity/Application/Worker/Activity）保留，逻辑类下沉 | settings.gradle.kts L55 注释的既定方向 |
| 统一 compileSdk（已收敛单 37：26 个 AAR 声明 minCompileSdk≥37，单 36 不可行；appTargetSdk 已降 36，待真机实测） | ci.yml 单 37 安装+断言 + gradle.properties 注释 |
| 死编号清理：`TODO P5/P7`、`M6 契约` 改写为 issue 或新任务描述 | 全仓 33 处 |
| 删脚手架：P3aVerificationScreen、CookieSmoke、IsDebugBuild 假实现 | desktopApp |
| 站点热切换 + 双源弹幕边缘收尾 | git log 最新三个 fix |

**DoD**：`:app` 只剩纯入口；CI 不再需要双 SDK 版本特判；全仓 grep 不到 P5/P6/P7/M6 编号；自用一周无站点切换/弹幕 bug。

### Gate 2「功能纵深」——竞争力主战场

| 方向 | 内容 | 备注 |
|---|---|---|
| 源站覆盖补全 | 作者页（`/user/{id}` 详情+作品列表）、系列清单（`/playlist`）先行；comic 子站延后 | 复用 `site/hanime1` 解析体系；comic 归档设计保留 |
| CF 攻坚 | 自动过盾（WebView 自动收割 cookie 等方案），手动 cookie 保留为降级路径 | **时间盒 spike**：风险最高，失败不阻塞其他项 |

> 2026-09-23：播放器方向**整体移出**本 Gate，独立为 Gate 3。
> 已在本 Gate 完成的播放项（画面比例/画面调节 `G2-3b`、系列自动连播 `433ac4f`）作为历史保留 `G2-3*` 编号，**不改号**；
> 播放模块的新工作一律挂 `G3-*`，对照表 `docs/specs/2026-09-20-G2-播放器对照表.md` 继续作为能力清单有效。

**DoD**：作者页/系列清单/comic 三平台可用（comic 可延后单列）；CF 自动过盾有实测成功率数据（或明确失败结论+降级方案）；**播放器功能清单对齐 animeko 对照表（功能缺失项的处置在 Gate 3，本 Gate 只对齐"有没有"）**。

### Gate 3「播放模块打磨攻坚」——把缝补上，再谈对齐（2026-09-23 新增）

> 独立的理由：Gate 2 的验收只管"功能有没有"，而播放模块剩下的全是**引擎抽象缝**带来的
> 质量债——换不换 mediamp、预览帧怎么接、超分是不是真的、控件状态机要不要重写。
> 这些**必须先有一个裁定**（否则会一路带到发布），且它们彼此耦合，拆进 Gate 2 的三方向里
> 谁都看不全。故单列，且排在「齐整」之前：带着一条假的引擎抽象去做三平台对齐，对齐的
> 是三个各自为政的实现。

来源文档：`docs/播放页-对比animeko差距清点与重构裁定.md` + 其审阅 `…-审阅.md`。
任务规划：`docs/specs/2026-09-23-Gate3-播放模块打磨攻坚-tasks.md`。

| 事项 | 说明 | 依赖 |
|---|---|---|
| G3-7 播放器稳定性回归 | 白屏/闪烁历史问题（468092b / f9d2cad / f4c2e4a）建回归测试，护航上面所有改动 | 无，**最先做** |
| G3-10 超分性能与掉帧治理 | 开超分画面卡顿 + 弹幕抖动（实测）。三重叠加开销 + 无分辨率门控；先加帧时间实测 | 无，**次优先** |
| G3-9 画面比例三端拉齐 | UI 链路已通，缺在能力表：Exo 无 Stretch、System 内核无菜单 | 无 |
| G3-1 超分诚实化 | Exo 路径实为同分辨率锐化（`ExoSuperResolution.kt:100-104`）：接真 Anime4K CNN 链或改文案 | 与 G3-10 合并推进 |
| G3-2 弹幕两处外科手术 | 帧时间 PLL 平滑 + 文本一次栅格化后 `drawImage`；闭式几何不动 | 排在 G3-10 后（PLL 救不了掉帧） |
| G3-3 控件状态机 | 可见性改请求方集合、手势挂载期仲裁；含"横向手势每帧无节流 seekTo"这个正确性 bug | 无 |
| G3-8 引擎测试补位 | 补 Android 三引擎（Exo/System/mpv-android）覆盖；需先建 android 测试源集 | 无 |
| G3-0 换底裁定 | `PlaybackEngine` → mediamp 是否执行；先向 mediamp 上游确认 Android mpv 后端是否存在 | 决策项，**允许裁定为"不换"** |
| G3-5 缓冲/卡顿语义对齐 | 桌面/iOS `bufferedPositionMs` 造假、mpv-android `isBuffering` 靠猜 | 依赖 G3-0 |
| ~~G3-4 预览帧管线~~ | **不做**（2026-09-23 产品取舍）：Android 侧破坏性语义，跨端不一致不如不做 | — |
| ~~G3-6 字幕/音轨选择~~ | **不做**（2026-09-23 产品取舍）：单音轨源为主，不换底则规模 XL | — |

**DoD**：播放模块无"假装实现了"的能力（缓冲进度、`isBuffering`、Android 超分三处语义造假清零）；
画面比例在三端 × 三内核下与真机实测一致；开超分不掉帧、弹幕不抖且有帧时间实测数据；
G3-7 的回归测试进 CI；换底与否有明确结论（**允许为"不换"**）并写进 ROADMAP。

### Gate 4「齐整」——三平台功能对齐（原 Gate 3）

| 事项 | 说明 |
|---|---|
| 平台能力补位 | iOS 触感/相册写入/ImageLoader/下载收尾，桌面下载收尾、调试构建对话框 |
| Gate 2/3 新功能三平台查漏 | 新功能开发时即三平台同步写，此处只查漏（含 Gate 3 的播放改动） |
| 性能基线 | live test 加门槛/隔离策略（当前随 desktopTest 默认跑、需联网），列表滑动/搜索响应建基准 |
| 下载链路三平台拉齐 | 桌面/iOS 收尾（引擎骨架已有，VideoCacheStore 仍 no-op；PlatformStores stale 注释同步更新） |

**DoD**：全仓无占位型 no-op（平台本无语义的 by-design no-op 除外，如截屏保护桌面/iOS、DNS+iOS 等，需注释标明）；三平台功能清单逐项打勾；播放器连续自用两周无崩溃/白屏。

### Gate 5「发布」——GitHub 开仓（原 Gate 4；发布标准维持不变：三平台齐整、无占位、体验对齐 animeko）

- README（定位/截图/三平台构建说明）+ 旧 `docs（不做参考）` 目录处置 + 断链修复（README 引用的 `定位.md` 缺失、iOS“规划中”已过时）
- Release 流水线：tag 触发 → APK（arm64）+ 桌面安装包 + iOS 源码说明，签名、changelog
- 敏感信息终检（local.properties、镜像 URL、cookie 处理路径、AppUpdateChecker 硬编码 update URL）
- 合规终检：NOTICE、aboutlibraries 第三方许可、上游许可声明
- 版本命名定夺（当前 26.3.2 日历式 vs 语义化）
- 仓库卫生：issues 模板 + .gitignore 复查（iosApp/build 产物是否误纳）

**DoD**：陌生人 clone 后按 README 三平台都能构建出可用产物。

## 5. 维护机制（防再次烂尾）

- **单一真相源**：`docs/ROADMAP.md` 一页纸（**2026-09-23 已建立**），只维护 Gate 进度和 DoD 勾选，不写长文
- Gate 3（播放攻坚）/ Gate 4（齐整）内部允许拆轮次，Gate 间顺序不跳
- 上游同步：每月一次 cherry-pick 窗口，解析逻辑修复优先，UI 不动
- 决策记录：重要取舍写 commit message，不另开文档
- 旧编号（P/M 体系）彻底废弃，新任务一律挂 Gate 编号
- **编号约定**：历史已完成标记（`G2-3b` 等）不回改，它们记录的是"在哪个 Gate 里做完的"；
  新工作挂所在 Gate 的编号。判定方法：看它指向的是**已完成的过去**还是**未开工的未来** ——
  前者保留，后者必须跟随 Gate 重排同步改号（2026-09-23 一次改了 13 处 `Gate3-平台能力` → `Gate4-平台能力`）

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| CF 自动过盾失败或不可持续 | 时间盒管理，手动 cookie 流程永久保留为降级路径 |
| iOS 无付费账号限制分发 | 定位已明确为源码+侧载文档，不追 TestFlight |
| Gate 2 体量大导致节奏失控 | 每完成一个纵深方向即在 ROADMAP 可见进度；CF 攻坚独立时间盒不阻塞其余 |
| **Gate 3 换底 mediamp 规模失控（L~XL）** | 预览帧与字幕音轨已决策不做，换底只剩 G3-5 一个下游 —— **可直接裁定"不换"**，把资源转投 G3-9/G3-10。若要换，先确认 mediamp 是否有 Android mpv 后端 |
| **超分开销打垮帧率，连带弹幕抖动** | G3-10：先加帧时间实测再优化（分辨率门控 / `dscale` 换便宜算法 / QUALITY 链裁剪 / 默认档位下调）。注意弹幕 PLL 只能摊平抖动，**救不了掉帧** |
| **画面比例三端能力不齐（Exo 无 Stretch、System 无菜单）** | G3-9：真机验证优先于写码；不支持的档在 UI 上如实说明，不做"选了没反应"的假开关 |
| **播放改动重演白屏/闪烁（历史两次 revert）** | G3-7 稳定性回归测试**先于**其余播放改动落地，且进 CI |
| 单人+AI 长线作战疲劳 | 每道 Gate 都是独立冲刺，DoD 即休息点 |
