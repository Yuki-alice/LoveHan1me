>    GPL-3.0——与本仓 GPLv3 全兼容。`gradle.properties` 里 `0.3.1-dev` 是占位符，
>    版本号由 CI 从 tag 注入， 不代表代码版本。
> 3. **animeko 超分已读完**（AGPLv3，只搬设计）：
>    Android 只跑 Exo 后端；PERFORMANCE = Restore CNN S（4 pass + 2 FP16 ping-pong，
>    同尺寸）；QUALITY = Restore CNN M + Upscale CNN x2 M（7+7 卷积 + combine +
>    depth-to-space，输出 2x）+ 落地 Lanczos scaler；桌面 mpv 挂 glsl + 缩放属性；
>    iOS 无超分。可搬三件：`//!DESC` 切分+模板注入形态、分辨率门控
>    （`needsUpscale`，viewport/video > 1 才生效）、预建空 effect 图免重建。
>    失败降级保留我们自己的（吞异常回 OFF，比它抛 `VideoFrameProcessingException` 稳）。
>
> 路径简写：`S/` = `shared` 模块；`P/` = 新 `:player` 模块（`player/src/<sourceSet>/…`，

## 4. P4 超分（与 P5 无关，可并行；建议与 P5 同一拨人做）

> 落地（2026-09-24）：下述 1-4 全做完；双端编译 + `:player` 42 / `:shared` 368 全绿。
> 偏差：自动化帧时间测量未建（无设备无流，测不了），门控决策沿用 animeko 已验证形状；
> 真机 QA 清单见末尾。

1. **分辨率门控**（已做）：mpv 双端 `needsUpscale`（渲染面/片源最小边比 > 1），
>   否则档位按 OFF 处理（清 shader + 还原缩放）；尺寸未知不门控（宁花算力不静默关功能）。
>   桌面读 `dwidth/dheight`，Android 用已缓存的 Surface 实测尺寸（比问 mpv 准）。
2. **`dscale` 换 bilinear**（已做，一行）：缩小路径不再吃 ewa_lanczossharp；
>   scale/cscale 保留 lanczos。
3. **预建空图免重建**（已做）：Exo 首 prepare 同步挂空表（档位恒从 OFF 起，不变量已注释），
>   切档热换 `setVideoEffects`（Media3 1.10.1 ≥ animeko 验证过的 1.9.0 同 API）；
>   删重建续播整段 + `lastRequest`/`lastSpeed` 两个死字段 + 倍速恢复补丁（不再需要）。
4. **Exo 真 CNN 链**（已做）：PERFORMANCE = 官方 Restore S（4 pass + 2 FP16 ping-pong，
>   同尺寸）；QUALITY = 还原 M + 放大 x2 M（7 卷积 + 合并 + depth-to-space，输出 2x），
>   真需放大且视口已知才接自研 lanczos 落地 scaler；无需放大只做还原 M；
>   视口未知不接 scaler（由 Media3 缩 2x 到渲染面）。
>   实现：`ExoAnime4kPasses`（common 纯构造：切分/前导/特征扫描，单测覆盖）+
>   `ExoAnime4kPrograms`（GL 装配：conv 链/combine/depth-to-space/scaler）。
>   模板与胶水全自写（AGPL 零复制）；权重体取仓内 MIT 文件，运行时切分。
>   失败语义保留：编译/资产异常抛给引擎降级 OFF（不断播）。
>   已知风险（与 animeko 同 profile，需真机确认）：depth-to-space 的动态向量下标、
>   scaler 为自研近似（非逐字复刻 ewa 链）、各档位帧时间无实测。
>
> 真机 QA 清单（有设备后补，补完才算 DoD 关闭）：各档位（OFF/PERF/QUALITY）×
> 各分辨率（720p/1080p 源 × 窗口/全屏）帧时间分布 + 输出分辨率确认 +
> PERFORMANCE/QUALITY 肉眼对比（纹理糊/振铃/噪点放大三看）；
> 不过线则把 QUALITY 降回还原 M 或标实验档。

## 5. P5 mediamp 0.5.0 迁移（`P` 内新增适配器，S 零改动）

目标：Android → exo 后端、iOS → avkit 后端、桌面不动。
依赖从 `0.3.2` 升 `0.5.0`（0.5.0 要 CMP 1.12+，本仓已满足；顺手删桌面
`LocalWindow` 垫片，0.4.0+ 用公开 `LocalAwtWindow`）。

| 适配器 | 内容 | 估算 |
|---|---|---|
| Android exo | `MediaData`（header/代理/ECH 经 `mediaSourceInterceptor` + `configurePlayerBuilder`）+ `PlayerState`→`PlaybackEngineState` 映射 + 音量直调 exo（无 `AudioLevelController`）+ 超分走 P4 链 + aspect 声明 Fit/Crop（player 层内存值假的无所谓，真效果走它家 Surface，见下） | 250~350 行 |
| iOS avkit | 同上 + `configurePlayer`；无超分（`supportsSuperResolution=false`，菜单自动隐藏，与现在一致） | 200~280 行 |
| `MediaData` 适配层 | 自定义 UA + 代理 + ECH 改写（`mediaUrlForGate` 路子后端无关，沿用） | 两端共 250~400 行 |
| Surface 跟换 | Android/iOS `PlatformVideoSurface` 改用 mediamp 自家 Surface（否则 aspect 假）；桌面已是它家的，不动 | 100~150 行 |
| 测试重写 | `IosAVPlaybackEngineTest` 等按 mediamp 形态重写 | 400~600 行 |

- `SystemPlaybackEngine` 删除（mediamp 无对应）。
- **Android mpv 内核去留未定**：`switch_player_kernel` 是现有产品功能。
>   留 `MpvPlaybackEngine` 当唯一例外（改动最小，不叫统一），或砍掉（最干净，需产品点头）。
>   P5 开工前必须先定，否则适配器范围不定。**这是本规划唯一的待定决策。**
