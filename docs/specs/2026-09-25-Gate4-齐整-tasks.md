> 前置：Gate3 已关（`:player` 独立 + mediamp 0.5.0 换底 + Android mpv 砍掉，

>
> 工作纪律（单人多 agent 多设备，防自己踩自己）：
> 1. 同一时间只让一个 agent 动树；换 agent/换设备前必须 commit + push，开工前 pull。

> 3. CI 为准：Windows（双端编译 + 双模块 desktopTest/hostTest）+ macOS（双模块 iOS 编译）。
>    iOS 单测执行与真机播放只在有屏 Mac 上跑，不进 CI。

### 2.1 本轮实测发现（P0，已修 / 缺口已定级）

- **启动崩溃（已修）**：arm64 真机/模拟器启动即崩（`libchino.so` 缺失）。
>   根因：46b4dea 删 NDK 源码时断言"全仓无引用"是错的，`MainActivity` 仍在加载；
>   且该库 JNI 符号包名前缀是上游旧包名，在我方包下永远链不上、全仓无 `external fun`。
>   修法：删加载块（不重建 NDK）+ 注释留证。x86_64 调试模拟器因守卫跳过加载故此前无人发现。
>   教训：删原生链必须跑一次 arm64 冒烟（现 emulator 已就绪）。
- **Android 无 ECH 网关产物（缺口，非 bug）**：`EchGate: 当前平台无 ECH 网关产物，直连降级`，
>   受限网络下 CF 挡站（`HanimeNotFoundException`），首页内容加载失败 UI 正常工作
>   （失败卡 + Retry，不崩）。iOS 有 xcframework 故模拟器能播，Android 要播站内容
>   需另立项移植网关（gomobile AAR，**不在 Gate4 scope**，记入 Backlog）。
>   本轮 Android 播放验证改用公网 bipbop 流，不依赖站点。
- **instrumented runner 缺依赖（已修）**：只声明 ext.junit 会导致 APK 无
>   `AndroidJUnitRunner`，`connectedAndroidTest` 起不来；补 `androidx.test:runner`。

| 机器 | 覆盖 |
|---|---|
| Windows（你的） | 桌面端全量 + Android（emulator 或真机：装 APK，跑播放/下载/设置页） |
| Mac（本机） | 模拟器 iOS 全量（已验证管线，bipbop 公网可达即转真跑）+ 桌面 macOS 冒烟 |

## 3. G4-3 性能基线（先有数，再谈优化）

1. live test 加门槛：现有 live 测试（播放/质量切换/站点抓拍）只验"不断言崩"，加帧时间/超时
>   分级（慢≠挂，超时才红），网络抖动不误报。
2. 隔离策略：live（要网）与纯单测分 job/标签，CI 默认只跑纯单测，live 手动触发
>   （Windows CI 出网不稳定已有先例）。
3. 列表滑动/搜索响应基准：首版只记录（trace + 帧时间日志），不设红线——
>   红线等 Gate4 末有数再定，避免拍脑袋。

## 4. G4-4 下载链路拉齐（本 Gate 唯一硬骨头）

现状：`DownloadWorkController` 三端都有真实现（desktop/iOS 文件均在），
缺的是 `VideoCacheStore` 在桌面/iOS 的真实现（两处 no-op）+ `PlatformStores` 注释同步。

- 先定语义：VideoCacheStore 存什么（已播位置？离线文件索引？）、谁读写、TTL——
>   把接口契约写清楚再动手，不清楚就先freeze no-op 并写明（DoD 允许 by-design 项）。
- 再实现：桌面（JVM 文件）/ iOS（沙盒文件）各一份 + 跨端一致的过期/清理。
- 验收：下载→断网→续播链路在三端走通；`PlatformStores` stale 注释更新。

## 6. 建议执行顺序

| 序 | 事项 | 机器 | 理由 |
|---|---|---|---|
| 1 | G4-1 小项（1-6、8） | Mac + Windows 分头 | 独立、快，先清掉 12 处标记 |
