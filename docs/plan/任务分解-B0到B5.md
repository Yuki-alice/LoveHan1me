## 二、D2-c 落地设计（B3 的前置，先定这个）

### 2.1 决策

**D2-c（全自动）+ clearance 前置检查作为可配置策略（默认开）**

```kotlin
/**
 * 自动镜像切换的前置策略。
 *
 * 背景：`cf_clearance` 按 CF zone 签发，四个域名分属不同 registrable domain ⇒ 必然不同 zone
 *（见验证报告 §4）。自动切到"无 clearance 存档"的域必然弹验证窗——那不是"无缝"。
 */
enum class AutoMirrorGuard {
    /** 默认：只在目标域已有 clearance 存档时自动切；从未访问过的域不切（改由 UI 提示）。 */
    RequireClearance,

    /** 逃生舱：无条件自动切，接受目标域可能弹一次验证窗。 */
    Always,
}
```

**为什么做成可配置而不是写死**：两种取舍都合理（严格=不打断，宽松=可达性优先），而**翻转只是一个枚举值**。
若将来发现严格模式导致"自动切换几乎不生效"，改默认值即可，不必重构。

### 2.2 新增能力：轻量切换 `autoSwitchTo()`

当前 `SiteSwitcher.switchTo()` 会**递增 `generation`**，而 `App.kt:161` 的 `key(generation)` **重建整棵 composition**（nav 栈上所有 VM 重置）。
对"用户手动点切换"这是对的（干净的软重启）；但**对自动切换是错的**——用户正在看页面，不能因为后台换了个镜像就把界面推倒重来。

**设计**：

```kotlin
/**
 * 自动切换（轻量）：只改站点坐标 + 复位出口现实，**不递增 generation**。
 *
 * 与 [switchTo] 的四处刻意差异：
 * 1. **不动 `selectedBaseUrl`** —— 那是"回程目标"语义（上次离开番剧站时记下的），
 *    自动切换不该改写用户的回程意图；
 * 2. **不清 cookie** —— 登录态是全局 `loginCookie`（对新 host 自动注入），
 *    而旧站响应带来的 host-scoped cookie 存在 `cookieMap[oldHost]` 下，天然隔离。
 *    清掉反而会丢掉用户下次访问旧站时的会话凭据；
 * 3. **不动 CSRF 槽位** —— `CsrfTokenProvider` 本就按站分槽（`siteTokens[host]`），
 *    自动切换天然正确，无需 stash/restore；
 * 4. **不递增 generation** —— 不重建 UI、不丢 nav 栈。调用方（失败的那次加载）
 *    自己重试并写回当前 VM。
 *
 * 代价（诚实记录）：其他 VM 可能仍持有旧站数据，直到它们各自重新加载。
 * 这与既有取舍同级——`switchTo` 的 KDoc 已声明"跨站隔离是独立议题，不在热切换范围内"。
 */
suspend fun autoSwitchTo(domain: String)
```

**调用约束**：只由"当前域加载失败"触发，且**必须由发起请求的那条链负责重试**，不做后台静默切换。

### 2.3 在 B3-4 里的位置

```text
① 探测/加载失败 → RouteHealth 记失败
      │
      ▼
② 该域熔断（或失败达阈值）
      │
      ▼
③ 选备用镜像（按延迟升序，取首个）
      │
      ▼
④ AutoMirrorGuard 前置检查
   ├─ RequireClearance 且目标域无 clearance → 不切，走 UI 提示（可一键切）
   └─ 通过 → autoSwitchTo(domain)
      │
      ▼
⑤ 调用方重试原请求（成功则用户无感）
```
