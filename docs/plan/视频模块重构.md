# 活计划：视频模块重构

唯一活计划（取代并收编了原「播放模块真值归一」的 D1–D14）。
执行完按 `AGENTS.md` 的规则把结论分流进 `decisions.md` / `evidence/`，然后删掉本文件。

## 目标

把视频模块从「一个塞满实现的巨型屏幕 + 一个什么都放的接口」重构成**契约 / 引擎 / UI 三分**，
分层骨架照 animeko 的 `video-player`（`api` 与 `ui` 分离、领域层不依赖 UI 层），
内容域按我们的站点裁剪。

症状（用户 2026-09-25 点名，仍然成立）：画面与渲染、播放状态错乱、平台间不一致、弹幕显示串集。
用户 2026-09-26 拍板：内核与超分实现**不重做**，重做的是**组织形态**；原真值归一的 D1–D14 收编进本计划。

## 前置事实（核过，不是假设）

- **内核已是 mediamp 0.5.0**：`player/build.gradle.kts:34` `implementation(libs.mediamp.api)`，
  三端后端 exoplayer / avkit / mpv-desktop，版本钉在 `gradle/libs.versions.toml:66`。**本计划不动内核。**
- **`:player` 对 mediamp 是 `implementation` 而非 `api`**，`:shared` 用 `api(project(":player"))`
  （`shared/build.gradle.kts:114`）并在 iOS framework 里 `export`（`:53`）。
  `shared/src/` 全量搜 `org.openani.mediamp` **零命中**。这条约束是本计划所有分层设计的硬边界：
  **契约层与 UI 层都不得碰 mediamp 类型**，否则会漏进 iOS 导出框架。
- **超分已双端落地**：桌面 mpv `change-list glsl-shaders`
  （`player/src/desktopMain/kotlin/lovehan1me/feature/player/DesktopMpvPlaybackEngine.kt:415`）、
  Android Media3 GL effect 链。**本计划只改它的挂载方式，不改实现。**

## 目标分层

```
:video:contract   新。纯 Kotlin，零 Compose、零 mediamp。
                    PlaybackCommand（密封）/ PlaybackState（快照）/ PlaybackEvent（SharedFlow）
                    PlaybackState 内请求值与真值**分列同名不同字段**
                    PlaybackCapabilities（能力声明，取代 supportsXxx() 默认实现）
                    VideoEnhancementController 抽象（commonMain 定义 + 各端 actual，null = 不支持）
                    DanmakuTrack 契约与几何（解算算法不动）
:video:engine     由 :player 改名而来。三端 mediamp 实现 + 共享派生函数。
                    依赖：contract + mediamp-*（implementation）
:video:ui         新。Compose。VideoScaffold 槽位化 + 控件 + DanmakuLayer。
                    依赖：contract + Compose；**不依赖 engine**
:shared           领域编排。VideoRouteHostScreen 瘦身为「播放会话（领域）+ 页面装配（UI）」。
                    依赖：contract + engine + ui
```

依赖方向因此可强制：领域层不依赖 UI 层，UI 层不依赖引擎实现。

## 从 animeko 搬什么 / 不搬什么

**搬（通用架构，与内容域无关）**
- 命令 / 状态 / 事件三分，状态用 StateFlow 快照 data class。
- **请求值与真值同快照分列**：参照 animeko 用 `playWhenReady`（意图）与 `isBuffering` / `MediaStatus`（真值）分工 ——
  这正是 D1–D5、D13 的根因解药。
- 能力声明取代默认实现：不支持即返回 null，UI 整块隐藏（解 D14）。
  参照 `reference/animeko/app/shared/video-player/src/commonMain/kotlin/videoenhancement/VideoEnhancementController.kt`。
- 槽位化组合：`reference/animeko/app/shared/video-player/src/commonMain/kotlin/ui/VideoScaffold.kt`
  （video / danmakuHost / gestureHost / topBar / bottomBar / rhsSheet）。
- 控件可见性的**请求者令牌**仲裁：
  `reference/animeko/app/shared/video-player/src/commonMain/kotlin/ui/PlayerControllerState.kt`
  （`SnapshotStateList` + `derivedStateOf` 定优先级，取代 D11 的多个布尔量互踩）。
- 领域态机与引擎态机正交分离（animeko 的 `VideoLoadingState` 与引擎 `PlaybackState` 是两个）。
- 弹幕两处外科手术：文本一次栅格化
  （`reference/animeko/danmaku/ui/src/skikoMain/kotlin/StyledDanmaku.skiko.kt`，离屏渲染成 `ImageBitmap` + `prepareToDraw()`）
  与帧平滑（`reference/animeko/danmaku/ui/src/commonMain/kotlin/FrameTimeSmoother.kt`，PLL 消抖）。

**不搬**
- **不抄页面结构与外观**。`decisions.md` B 节「向 animeko 靠拢的正确落点是播放底座 mediamp，不是抄它的 UI」，
  且「四处不得因对齐 animeko 而回退」（双皮肤结构、右栏配色跟随主题、时间文字描边 + `tnum`、亮度能力探测）。
  本次搬的是**分层与状态契约**，不是 UI。
- 不搬番剧域输入：数据源×字幕组线路（`MediaSelector`）、BT 与 HLS 代理、章节 / OP-ED 跳过
  —— 均为 `decisions.md` A 节范围外或我们无输入的部分。
- **弹幕解算不重写**（`decisions.md` C 节）；只做上面那两处手术。`DanmakuItem` 在 `:player` 与 `:shared`
  的两份是**有意拆分**（包名不变、注释写明），不是重复，别当缺陷合并。

## 先写红测试（改代码之前必须先失败）

- T1 `load()` 写的 Error 不该被下一次 publish 抹掉 —— 断言 D2
- T2 切画质期间海报不得闪回 —— 断言 D3
- T3 `durationMs` 在 props 尚未就绪时不得被 0 覆盖 —— 断言 `MediampPlaybackEngineBase.kt:256`
- T4 倍速设置失败（引擎不支持）时 UI 不得停在请求值 —— 断言 D4
- T5 aspect 设为 no-op 的模式时不得重建 Surface —— 断言 D9
- T6 `isBuffering` 三端语义一致 —— 对照 `MediampPlaybackEngineBase.kt:254` 与 `DesktopMpvPlaybackEngine.kt:126`
- T7 去掉 write-once 护栏后错误信息仍只写一次 —— 断言 D5 的护栏可以被纯派生取代
- T8 切画质失败时 `isSwitchingQuality` 不得永久卡在 true
- T9 引擎模块不得再出现 `androidx.compose` import —— 断言 D15（用源码扫描测试守，搬家后不许回潮）
- T10 超分档位落盘后重进播放页仍生效 —— 断言 D13

测试落点：契约层的 `commonTest`（经 desktop 跑）。T1–T8、T10 纯逻辑不碰 Compose；T9 是源码扫描。
D10/D11 属可见性缺陷，**必须有可交互测试**才算修完（见验收）。

## 步骤（严格按序）

1. **契约先行**：建 `:video:contract`，只写类型与纯函数，不改任何现有实现。
   产出 `PlaybackCommand` / `PlaybackState`（请求值与真值分列）/ `PlaybackEvent` /
   `PlaybackCapabilities` / `VideoEnhancementController` 抽象 / `DanmakuTrack` 契约。
2. **红测试**：T1–T10 全部红。
3. **单写者改造**：`derivePlaybackState(snapshot, props, requested, seen, prev)` 纯函数化落到契约层，
   `mutableState` 收私有；删掉 `MediampPlaybackEngineBase.kt:86` 与 `:110` 两处命令式写。
   三端引擎改为唯一写者。做完 T1/T2/T3/T7/T8 必须转绿。
   桌面并轨顺手处理 D7；**D8 的反射先取证再动**：mediamp 0.5.0 的 `JvmMpvMediampPlayer`
   已带 `attachRenderSurface` / `renderContextBecameReady` / `hasActivePlaybackSession`，
   若真首帧信号已能拿到，就删掉所有「近似首帧」的猜测。
4. **模块三分**：`:player` → `:video:engine`，建 `:video:ui`。
   `DanmakuLayer` 迁进 ui（D15）、`ComposePlaybackController` 归位并改名（D16）。
   `shared/build.gradle.kts:53` 的 `export` 要跟着覆盖全部新模块，否则 iOS 侧看不到类型。
   D17 **先做依赖分析再删**，弱证据不足以动手。
5. **超分抽离**：`PlaybackEngine` 的 `setSuperResolution` / `supportsSuperResolution`
   （`PlaybackEngine.kt:111`、`:120`）迁出为 `VideoEnhancementController`，不支持即 null、入口整块隐藏（D14）。
   同时给档位落盘（D13）—— 按 `decisions.md` F 节，改默认值语义必须同时回答「老存档已落盘的旧值怎么办」。
6. **UI 槽位化**：`VideoRouteHostScreen`（1120 行）拆成领域会话 + 页面装配，
   引入槽位化组合与请求者令牌仲裁（D9–D12）。D10、D12 是两条独立小修，可先行。
7. **弹幕两处手术**：帧平滑 + 文本一次栅格化。解算算法与 `decisions.md` C 节「不要动四件」原封不动。

## 本计划不做

- 不动 mediamp 版本与内核选型（桌面继续 mpv，`decisions.md` B 节）。
- 不重写超分实现。
- 不重写弹幕解算。
- 不动 `decisions.md` C 节的四件「不要动」清单。
- 不把 mediamp 类型引进 `:video:contract` / `:video:ui` / `:shared`。
- 不给性能基线定阈值。
- 不抄 animeko 的页面结构与外观。
