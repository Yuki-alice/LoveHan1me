## B2｜首页虚拟化（已落地 2026-10-05，按 dual-skill 执行）

- 落地（`optimizing-lazy-layouts` item hygiene 优先，`configuring-lazy-prefetch`
  约束为王）：
  1. `HanimeInfo.itemType` var→val（全仓无写入点）+ `VideoItemType` 标
     `@Immutable`（三实现全 val，诚实不断言）→ `VideoCardItem` 可跳过，
     滚动不再逐帧重组卡片。
  2. 首页外层 heterogeneous 加 `contentType`（banner/update/announcement/category）。
     网格类列表本就 key 正确、单构型，依 skill 可选条款不动。
  3. 重试去 URL 污染：`?retry=` 同时击穿三级缓存，改同 URL + 磁盘 bypass 重发。
  4. 首页封面预热（`ImageLoader.enqueue`，只写磁盘不写内存，封顶 12 张，
     方向反转浪费可控）——激进但有界，符合"不饿内容"要求。
- 刻意不做（附理由）：CategoryBlock 转 LazyRow（产品决策：桌面网格，一票否决）；
  CacheWindow 手动调窗（无帧指标支撑，属 skill 明令禁止的 premature tuning；
  现代 foundation 预取默认已够）；painter 上提（卡片有界，skill 要求 profiling 先行）；
  animateItem（feed 无 reorder 语义，120Hz 网格上动画成本大于收益）。
- 验证：三端编译过，全量 496/0；桌面实跑内容 3.3s（缓存命中）、零 CoilError、
  零崩溃。skippability 以编译器契约为据（未搭 compiler-reports 基建，
  如实记录）；帧率需真机 Macrobenchmark，列入 Open items。

## B2-D｜发现页（已落地 2026-10-05，与 B2 同批）

- D1 默认浏览 stale 缓存（E2 同款机制，`discover_` 前缀隔离）：
  每次进 tab 不再白等整轮网络，先展上次第一页再后台刷新。
  - 只缓存"无条件浏览"（page=1 + 无词无筛选无 broad）：key 本来就不含筛选参数，
    有条件的请求天然 miss，不会串结果；
  - 写路径：`pageIOFlow` 加可选 `onBody`（E2 同款，默认 null，其余调用点零影响），
    `getHanimeSearchResult(writeCache)` 透传；
  - 读路径：`SearchViewModel` 先读缓存 `Parser::hanimeSearch` 首展，
    新鲜第一页到达时**替换**（不是追加，去重保首项，追加会把旧快照顶前面）；
  - 已看标记内联逻辑抽 `withWatched()`，缓存首展与网络刷新共用；
  - 下拉刷新同样受益（先展旧页再覆盖）。
- D2 网格 `contentType = { it.itemType }`（normal/simplified 双构型混排不断言）。
- D3 新页预热：`takeLast(12)` 只热新到页（已热过的不重做，无 churn），磁盘-only。
- 刻意不做：列表截断（B3 独立项，语义变更另议）；筛选面板/历史建议（DB 防抖已有，无实测热点不动）。
- 验证：三端编译过；一次性 live 测试实证全链路（真页抓取→写透→读回→重解析，
  videoCode 序列完全一致，通过后已删）；全量 496 中唯一失败是 `EchGateLiveTest.javchu`
  —— 干净树同失败（预存环境问题，调度器/网关，非本次回归）。
  ViewModel 替换语义为 review 验证（headless 无网关 sidecar，走 appraisal；
  hook 形状与已上线的 E2 完全同构）。

## B3｜搜索结果封顶

- 现状：`SearchViewModel.kt:107` 的 `_searchFlow` 无界累加
  （见 `:147` 的 `update` 与 `:163` 的 `distinctBy`），20 页 × 24 条时
  `distinctBy` 的 O(n²) 比较与常驻内存随页数上涨；`getWatched` 批量虽已对，
  仍每页一次 DB。
- 改动：`takeLast(500)` 封顶或切 Paging3（二选一，动工前定；推荐前者，小）。
- 验收：20 页时内存常驻封顶，`distinctBy` 比较次数为常数。

## B5｜播放页高频重组隔离

- 现状：`DanmakuLayer.kt:76` 的 `frameNanos` 每 vsync 写 state
  （见 `:98` 的 `withFrameNanos`），`Canvas` 读它等于每帧重组；
  `MediaProgressSlider.kt:187` 的位置流每 250/500ms 产出新对象，
  `VideoRouteHostScreen.kt:179` 整 `PlaybackSessionState` 全屏重组。
- 改动：帧时钟改 `DrawScope` 内失效不写 `State`；位置流
  `conflate/distinctUntilChanged(200ms)`；屏幕只收
  `phase/isPlaying/isBuffering`，slider 单独收 position。
- 验收：播放页每秒全屏重组数下降一个量级（计数器为准）。

## B6｜图片定尺寸与稳定缓存键

- 现状：`Utils.kt:35` 的 `RetryableImage` 重试拼 `?retry=` 换 URL，
  必击穿磁盘缓存；无 `size()`/`memoryCacheKey`，解码按原图尺寸。
- 改动：`ImageRequest.size(Width/Height)` + 稳定 `memoryCacheKey`，
  重试走 Coil 内置 retry 不换 URL；网格加可见区预取。
- 验收：重试命中磁盘缓存，快滑图闪减半（主观 + 缓存命中日志）。

## B7｜备份流式化

- 现状：`BackupManager.kt:32` 的 `prettyPrint = true` + 先全拉 List
  再 `encodeToString` 一个大 String（见 `:75`），导入 `readUtf8` 全读
  再 decode（见 `:84`）。万级记录即数十 MB 峰值抖动。
- 改动：`prettyPrint = false`，`encodeToSink/decodeFromSource`
  或分表流写，`getAll()` 改分块 `LIMIT/OFFSET`。
- 验收：10MB 备份导出峰值内存降至 O(chunk)（profiler 为准）。
