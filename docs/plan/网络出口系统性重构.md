# 网络出口系统性重构

把"这次请求该从哪儿出去"从**散在 11 个网络栈里的隐式判定**，收成**一份显式的、可测的决策**，
并让网关从"必经的一层劫持"降为"候选出口之一"。

起因：网关被阻断后，用户原本可用的系统代理被整个绕开（根因与证据见工作区
`.workbuddy/artifacts/网络出口梳理与网关故障根因.md`，不进版本库）。用户已拍板三条，
见 `docs/decisions.md`。

## 目标形状

四条轴显式化，每条轴自带优先级、预算与**降级原因**：

| 轴 | 取值 | 谁决定 |
|---|---|---|
| 出口手段 | Gate / UserProxy(Http,Socks) / System / Direct | `EgressPlanner` |
| DNS | Gate 内 DoH / 内置IP自动 / DoH / 系统 / 内置IP强制 | `EgressPlanner` → jvm `HanimeDns` 执行 |
| TLS SNI | ECH / CNAME真名 / 明文 | 网关（应用侧只声明"交给网关"） |
| 栈 | OkHttp / mpv / CDP / Exo / WebView | 各栈只是 plan 的**执行器** |

核心不变式：**判定只有一个地方产出**（`EgressPlanner` 纯函数），**执行器不含判定**。
网关的可用与否由 `GateHealth` 熔断状态机回答，且"阻断"与"连接失败"都算失败。

### 增量二 —— 已完成并验证

把其余栈上"自己判断网关"的地方全部收进 planner。判定本体新增两个：
`GateState.isCandidate`（可用候选：开着 + 在跑 + 未熔断）与
`GateState.connectTunnelUrl()`（CONNECT 隧道），以及执行器入口
`EgressPlanner.gateRewriteFor()` / `EgressPlanner.mediaProxyUrl()`。

替换掉的五处自判断：

| 位置 | 原来 | 现在 |
|---|---|---|
| `ImagePipeline.kt`（Coil 图片栈，iOS 用） | `EchGatePolicy.rewrite(url, EchGate.port)` | `EgressPlanner.gateRewriteFor(url)` |
| `PlayerWiring.kt` 的 `gateRewrite`（mpv / Exo 共用） | 同上 | 同上 |
| `MediaProxyResolver.kt` 的 `gateConnectUrl` | `EchGate.port > 0` | **删除**，改用 `GateState.connectTunnelUrl()` |
| `PlayerWiring.desktop.kt` 的 `proxyUrlFor` | `resolveMediaProxyUrl() ?: gateConnectUrl()` | `EgressPlanner.mediaProxyUrl(...)` |
| `CloudflareCdp.kt` 的 `proxyFlag` | `EchGate.port > 0` | `currentEgressState().gate.connectTunnelUrl()` |

关键不变式**新增**：**隧道通道与改写道同源**。此前隧道只判 `port > 0`，于是
"改写道已被熔断摘掉、隧道却还在把流量往网关里送"是可能的 —— 而媒体没有回退，
撞不通就是直接失败。现在两条道一起出现、一起消失。

第二条：**验证窗在网关熔断/关闭时回落到用户代理**。对应根因 3 —— 网关不通时若仍
把验证窗押在网关上，用户连"做验证"这条唯一的自救通道都没了。

## 增量划分

按用户价值排序，每个增量独立可验证、可回滚。

### 增量一（本轮）：出口判定中心化 + 网关熔断

- `commonMain/egress/`：`EgressRequest` / `EgressState` / `EgressPlan` / `EgressPlanner`（纯函数）
  / `GateHealth`（纯状态机）。**零平台依赖，直接进 commonTest。**
- `GateHealth` 规则：连续 3 次失败**或一次"阻断类"失败**（403 / `you have been blocked` /
  `Just a moment`）即熔断；冷却 5 分钟后半开；成功即闭合。
  阻断类立刻熔断的理由：那说明网关的出口被封，重试只会继续消耗用户的耐心。
- `EchGateInterceptor` 改为读 plan：
  - 熔断期间**不接管**（等价于网关不存在，请求走代理/直连原路）；
  - 有可用代理时网关处于**试用期**：返回 403/502 且方法是 GET/HEAD ⇒ 恢复原 URL 经代理重试一次；
    只有"经代理重试拿到了非 403 结果"才判定网关有责并记失败（避免误熔断）。
- `EchGatePolicy.rewrite` 保留为 planner 内部的一个谓词，不产生第二份判定。
- `useEchGate` 改**条件默认开**：仅在用户没配可用代理时默认开启。
- 设置页展示熔断态（复用 `ech_gate_status_*` 一节，新增一条文案）。

### 增量二：其余栈接入同一份 plan

CDP 验证浏览器（`proxyFlag`）、mpv（`proxyUrlFor` / `rewriteForGate`）、Exo（`EchGateDataSource`）
三处改为消费 plan，而不是各自判断"网关在不在跑"。`EchGatePolicy` 之上的判断全部消失。

### 增量三：豁免显式化

DoH 客户端、更新检查、弹弹play 这三个"故意裸出"的网络栈，在代码里标注为**豁免**并给出理由，
不再是"看起来像漏了"。

## 不做

- **不引入中转服务端**（`POSITIONING.md` 红线）。
- **不改 `EchGatePolicy.rewrite` 的改写规则本身**（回环/IP 字面量/非 https 放行）——它是对的。
- **不动 iOS 播放链路**（`AVAssetResourceLoaderDelegate`），归增量二之后的独立议题。
