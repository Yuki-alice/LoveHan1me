### F2 为什么不按本文件字面改

本文件建议单条链 `隧道 → 用户代理 → 直连`。实际改为**按门面状态分两支**：
网关是可用候选 ⇒ `隧道 + addDirect()`；否则 ⇒ 用户手填代理（未配则不覆盖）。
理由是"出口对齐"本身：网关是候选时 App 的出口是**本机 IP**（代理选择器对回环短路），
隧道坏掉落到直连仍是本机 IP；若那时改落用户代理，出口变成**代理 IP**、与 App 反而不一致，
正是要消灭的"验证过了仍然要验证"。分两支同时补上了"网关关着 + 手填代理"时验证窗走系统代理
的真实缺口。判据仍只有一处：`currentEgressState()`。决策已入 `docs/decisions.md`。

### F1｜功能性缺陷：进程内起服器缺"停止期间起服"守卫

`AndroidEchGateStarter.start()` 在 `startFlat` 返回后**无条件**写 `server` 并 publish
`Running`（`app/src/main/kotlin/lovehan1me/echgate/AndroidEchGateStarter.kt:76`，**已修**：
现为 `server = started` 之后紧跟 `EchGateRuntime.publishRunningIfStillStarting(port)` 复查，
false 即 `close()` 并把这次起服当取消）；
首次 DoH 期间该调用最长阻塞 15 秒。若用户在这段窗口里关掉开关：门面已 publish
`Stopped`、`starter.stop()` 却看到 `server == null` 无处可停，随后起服线程把状态覆盖回
`Running`，留下一个**开关已关但仍在运行的网关**（设置页状态与实际不一致；Go 侧监听与
goroutine 常驻到进程退出或下一次切换）。

桌面端有对应守卫（`shared/src/desktopMain/kotlin/lovehan1me/data/network/DesktopEchGateStarter.kt:104`
在 spawn 后复查 `status is Starting`，否则就地销毁），Android 端漏了。门面测试只覆盖
"起服器返回 false"的路径，覆盖不到"返回 true 且补 publish"这一形态；
**已补**：`shared/src/desktopTest/kotlin/lovehan1me/data/network/EchGateRuntimeTest.kt:209`
（`起服期间被停止时就绪发布必须失败`）与 `停止时先落 Stopped 再回收资源`，反向验证 6/6 PASS。

修法（建议）：门面提供一处可测的发布入口，例如
`EchGateRuntime.publishRunningIfStillStarting(port): Boolean`（在就绪锁内复查
`status is Starting` 再 publish，false 表示已被停止）；Android 起服器改用它，
false 时 `close()` 并返回 false；`stop()` 与起服尾段串行化到同一把锁（对齐桌面的
`@Synchronized`）。同时补一条门面测试钉住该竞态。

### F2｜对齐项：验证窗回落档缺"用户代理"

`GateWebViewProxy` 的规则是 `隧道 → addDirect()`（`shared/src/androidMain/kotlin/lovehan1me/app/web/GateWebViewProxy.kt:58`，**已按分两支重写**，见下）。
桌面口径是：网关不可用 → 回落用户代理（`CloudflareCdp.proxyFlag`）。因此"网关可用但隧道
坏 + 用户配了代理"时，桌面直接失败、Android 落直连——建议 Android 补
`隧道 → 用户代理（若配置）→ 直连` 的中间档（格式按 ProxyConfig 支持的 scheme 对齐），
并把 KDoc 里"与桌面……同一考虑"的表述校正为准确描述。

### F3｜命名重叠（低优先）

jvm 侧新增接口 `EchGateStarter` 与 iOS 侧 Swift 回填对象 `EchGateStarter`（iosMain）同包
同名、分属不同源集：不冲突，但排查时容易混淆，建议后续把 iOS 对象改名（如
`EchGatePortReporter`），Swift 一并更新。
