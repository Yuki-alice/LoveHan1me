# 网络连接调度器重构（EgressScheduler）

> 前序：替代 `docs/plan/打磨阶段规划.md` 的 A 线（连接体验），旧文件随本规划落地归档删除；
> B 线（性能）与 C 线（全端适配）另立计划时再展开，见文末后接清单。
> 决策（已与用户确认，共 7 条）：国内受限网络优先、网关是主力；用户侧无缝切换 +
> 开发者诊断双层；按域独立熔断 + 按延迟与成功率动态择优 + 稳定时粘滞；
> 全栈重构；受限域跳过直连、失败时诚实报错 + 引导；只在失败时重选路由（零后台探测）；
> 保留手动强制选路逃生舱。
>
> 本文件所有引用均为实测行号：写每一节前已通读 `egress/` 全包、两执行器、三端工厂、
> 播放器接线、DNS/代理/CF 链路与现有测试。

## 2. 新架构（签名级）

```kotlin
// 域分类：决定"直连要不要试"。第三方域永不进网关（现状行为保留）。
enum class DomainClass { Hanime, Getchu, CdnMedia, ThirdParty }
fun classifyDomain(url: String): DomainClass  // hanime1系/host表/getchu固定 host/图床 host/其他

// 路由：网关改写道 / 用户代理 / 系统代理 / 直连 / 网关 CONNECT 隧道（播放器与验证窗专用）
enum class RouteId { Gate, UserProxy, SystemProxy, Direct, GateTunnel }

// 用途：EgressRequest 新增 purpose 字段（`EgressTypes.kt:19`，Phase 1 已落地）。
enum class EgressPurpose { Api, Image, Video, Download, Probe }

// 强制模式：Settings 新增 egressForceMode（Auto/ForceGate/ForceDirect/ForceProxy），
// scheduler 短路整份计划；ForceDirect 在受限域上弹警告（预期撞 RST）。
enum class ForceMode { Auto, ForceGate, ForceDirect, ForceProxy }

// 单步：路由 + 本步预算 + 失败后语义（下一跳由 scheduler 事先排好，执行器不决策）。
data class RouteAttempt(val route: RouteId, val budgetMs: Long, val rewrite: EchGatePolicy.Rewrite? = null)
data class ScheduledPlan(val attempts: List<RouteAttempt>, val skipped: GateSkipReason?, val domain: DomainClass)

// 每域健康：成功率窗口 + EWMA RTT + 熔断/半开 + 粘滞优选。全部纯函数，可离线断言。
data class RouteHealth(/* per-route: 近N次成败、ewmaRttMs、连续失败、熔断点、lockedRoute */)
fun RouteHealth.onResult(route: RouteId, outcome: AttemptOutcome, rttMs: Long): RouteHealth
fun RouteHealth.preferred(): RouteId?  // 锁定条件：连续 K 次成功且无熔断；失败即解锁重选

// 注册表：四域各一份 RouteHealth + 路由表；换网/切站时 reset(domain?)，挂进既有复位入口。
object RouteRegistry { fun healthOf(domain: DomainClass): RouteHealth; fun reset(domain: DomainClass? = null) }

// 调度器：替代 EgressPlanner.plan。受限域（Hanime/Getchu/CdnMedia）不排 Direct；
// 无代理且网关不可用 → attempts 为空 = 诚实失败，不转圈。
object EgressScheduler {
    fun plan(request: EgressRequest, state: EgressState, force: ForceMode = Auto): ScheduledPlan
}

// 上报：两执行器共用。outcome 含成功/传输异常/网关错误页/阻断码；rtt 只记完成步。
object EgressReporter { fun report(domain: DomainClass, route: RouteId, outcome: AttemptOutcome, rttMs: Long) }

// 诊断：ring buffer 近 200 条 {t, domain, route, outcome, rttMs, reason}；设置页展示 + 导出。
object EgressEvents { fun emit(e: EgressEvent); fun recent(): List<EgressEvent> }

// 诚实失败：attempts 为空或全部耗尽且直连被跳过时抛给上层，转 WebsiteState.Error 人话 + 设置深链。
class NoRouteException(val domain: DomainClass, val reason: String) : IOException
```

- 预算表（purpose × route，初值，Phase 2 实测调）：Api 走网关/代理沿用 15s/30s/60s；
  Image connect 沿用 5s（封面）/15s 并补 read 15s、call 30s；Video/Download 保持 connect 5s、
  不掐 read/call（流式），靠 stall 检测；Probe 沿用现值；Direct 只出现在非受限域。
- purpose 透传：OkHttp 侧由建 client 处打 `request.tag(EgressPurpose::class)`（hClient=Api、
  downloadClient=Download、getchuClient=Api、CdnFetchClient=Image，下载封面=Image），拦截器读 tag，
  无 tag 默认 Api；iOS 侧 Ktor `HttpRequestBuilder` attribute 同理，插件读取。
- 粘滞规则：优选路由连续 3 次成功锁定；任何失败解锁并按健康重排；熔断"阻断类一次、
  其余 3 次"、冷却 5 分钟、半开（语义见 `RouteHealth`）。
- RTT 采样：OkHttp 在 attempt 前后 `nanoTime`；Darwin 在 `proceed` 前后；只记完成步，
  超时/取消不记（避免污染 EWMA）。
- 就绪等待保留但收窄：执行器仅当首步是 Gate 且状态为 Starting 时调 `awaitReadyIfStarting`，
  预算计入该步 budgetMs，不再是计划外等待。
- CF 收敛：删 Android 拦截器内阻塞验证 + inline 重试，改为"标记 → 抛 → 总线"，
  与 body 路径同一触发点；等待只留 `ioRequest` 一处，总预算单值 150s 不变，
  三端精确 `cf_clearance` 判定补齐（含 iOS 前缀误判）。

  图床流量已喂 CdnMedia 域健康）；视频 outcomes 缺席不影响熔断（同域图片先熔）。
- 补丁（2026-10-04 桌面冒烟崩溃，exit 10）：崩溃报告钉死两条——
  (1) `NoRouteException` 是普通 `Exception`，OkHttp 只把 `IOException` 交给
  `Callback.onFailure`（Coil 图片走 `enqueue`），非 IO 异常从裸分发线程逃逸成未捕获；
  (2) 取消风暴（`IOException("Canceled")`）被当传输失败喂熔断，误熔 `CdnMedia` 后
  首个图片请求即 NoRoute，撞上 (1) 崩溃。修复：`NoRouteException` 改继承
  `okio.IOException`（JVM actual 即 `java.io.IOException` typealias，零新依赖；
  外层 Retry 照旧不重试它）；两执行器调用方取消不记账（OkHttp 以
  `chain.call().isCanceled()` 判，Darwin 以 `CancellationException` 优先透出）；
  Darwin 重试谓词抽取为纯函数并排除 NoRoute。回归：取消不喂熔断 /
  JVM 上 `NoRoute is java.io.IOException` / 谓词 3 用例。

3. 桌面：`./gradlew :desktopApp:run`；网关日志打到 stdout（找 `ECH 网关已就绪`）；

### 7.3 P5-1 调度逻辑验收（本机可执行，需 2 部"戏"：断网演熔断）

约定：每项记录三态文案 + 关键日志 + 诊断导出片段（设置→网络→连接诊断→复制）。

- T1 开关 off 即旧语义：关开关 → 浏览 200，三态无条，事件首步为 Direct。
- T2 开关 on 走网关：开开关 → 首步 Gate（事件 `Hanime Gate Success`），三态无条。
- T3 熔断（Android 模拟器）：`adb shell svc wifi disable` 后连续触发 3+ 次请求
  （下拉刷新/进详情），三态出现"已熔断"，事件出现 `Blocked`；
  `svc wifi enable` 后 `onAvailable` 复位，三态恢复干净。
  原理：断网制造传输失败攒熔断；`NetworkCallback` 只认 onAvailable，
  disable 本身不复位（见复位入口注释），顺序不能反。
- T4 熔断（桌面）：`pkill -f echgate` 后触发请求 ×3 → 三态"已熔断"；
  开关关→开（手动复位）→ 恢复。顺带验证"开了不管事"已消失。
  桌面换网无系统事件是已知限制：本项只验手动复位路径，不验自动监听。
- T5 诚实失败：网关开着 + 已杀 + 无代理（Direct 档）→ 页面是明确报错
  （非无限转圈），三态"无可用出口"。
- T6 强制三态：ForceGate / ForceDirect / ForceProxy 逐一切换，
  事件首步与所选一致；切回 Auto + 健康归零（切换即清注册表）。
- T7 诊断导出：复制文本粘出，逐行含时间/域/路由/结局/耗时/预算六字段
  （格式见导出函数单测，缺字段即失败）。
- T8 CF 与验证窗：本网大概率 N/A；若触发则按 7.4-R3 记录"验证后不再弹"。
- T9 覆盖缺口（如实记录，不编造）：Android 无法像桌面那样单独杀网关进程
  （gomobile 进程内起服），熔断 e2e 以 T3 断网法为准；桌面无换网监听；
  iOS 无设置页 UI（行为+日志为准）。
